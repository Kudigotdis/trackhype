# 15. 24-hour voting rule

I would change your current:

```text

```

system.

Instead store something conceptually like:

```text
lastVoteTimestamp
chartId
voteDate
```

The interface can say:

```text
VOTED

Next vote available in
23h 42m
```

But there is an important technical issue:

### `localStorage` is NOT sufficient for the real voting system.

Your existing HTML uses localStorage for voting and chart state. 

That is fine for a prototype.

It is **not sufficient for a real TrackHype chart**, because users can:

* clear browser storage
* change browser/device
* use another device
* manipulate local data

So the production system should eventually use:

```text
User ID
+
Chart ID
+
Voting period
+
Submitted order
+
Timestamp
```

on the server.

# 16. Global vote calculation

For a Top 20:

| Position | Points |
| -------: | -----: |
|       #1 |     20 |
|       #2 |     19 |
|       #3 |     18 |
|       #4 |     17 |
|      ... |    ... |
|      #19 |      2 |
|      #20 |      1 |

This is much cleaner than the current `* 15` implementation. 

And importantly:

**Do not immediately alter the visible chart when one person votes.**

Instead:

```text
User submits vote
       ↓
Vote recorded
       ↓
Daily tally database
       ↓
Aggregate all users
       ↓
Chart recalculated
       ↓
Next published chart
```

That prevents the chart from jumping around every time somebody votes.

# 34. One correction to the YouTube assumption

I would **not put this statement into the app documentation**:

> "Using YouTube shifts copyright liability to YouTube/content uploader."

That's too broad.

YouTube does permit embedding, and its official help specifically describes embedding videos on websites/apps, but the embedded player remains subject to YouTube's API Terms and Developer Policies. ([YouTube Help][3])

YouTube's terms also distinguish ordinary personal use from commercial/public uses and place responsibility for uploaded content on the uploader. ([YouTube TV][4])

So the safer TrackHype architecture is:

```text
TrackHype stores:
    YouTube VIDEO ID
    YouTube URL
    metadata

TrackHype DOES NOT:
    download YouTube audio
    convert YouTube videos to MP3
    host ripped audio
    strip YouTube advertising
    manipulate YouTube engagement
```

And the player remains the official embedded YouTube player.

That also fits your existing implementation, which already creates an official YouTube iframe from the submitted URL.
